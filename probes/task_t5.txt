Create ledgerkit/limiter.py with class TokenBucket(rate, capacity, clock=time.monotonic). rate is tokens per second, capacity the maximum. It starts full. try_acquire(n=1) returns True and takes n tokens if available, otherwise False and takes nothing. wait_time(n=1) returns seconds until n tokens would be available, 0 if available now, and takes nothing. Raise ValueError if rate <= 0, capacity <= 0, n <= 0, or n > capacity, for both methods. Refill is lazy and capped at capacity. If the clock goes backwards, no tokens are added or removed and the bucket continues from the new time without losing later refill. Accumulated floating point error must not be able to deny a request that is exactly affordable: after waiting exactly wait_time(n) seconds from an empty bucket, try_acquire(n) must succeed, even over thousands of cycles with rates such as 0.1, 3 or 7. All methods must be safe under concurrent threads, so N threads can never acquire more than the tokens that exist. Add tests in tests/test_limiter.py and run python3 -m pytest -q.
